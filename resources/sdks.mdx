Widgetic provides an SDK for calling the API from your server, an embed script for showing widgets on your pages, and a UI SDK for putting Widgetic's editors in your own page.

## JavaScript / TypeScript API SDK

The primary SDK for interacting with the Widgetic API from your server.

### Installation

<CodeGroup>

```bash npm
npm install @widgetic/api-sdk
```

```bash yarn
yarn add @widgetic/api-sdk
```

```bash pnpm
pnpm add @widgetic/api-sdk
```

</CodeGroup>

### Basic Usage

```javascript
import { WidgetsApi } from '@widgetic/api-sdk';

// Initialize with API key
const widgets = new WidgetsApi(process.env.WIDGETIC_API_KEY);

// Fetch widgets
const result = await widgets.getWidgets({ page: 1, size: 20 });
console.log(result);
```

Every method takes one request object, for example `getWidgets({ page: 1, size: 20 })`, and the body of a create call sits under a named key, for example `createManagedUser({ newManagedUser: { ... } })`.

<Tip>
  You can use either API keys (recommended for server-side) or JWTs depending on your integration.
  See [Authentication](/docs/authentication) for details.
</Tip>

<Warning>
  Call the SDK from your server, never from a browser page: a key in a page can be read by every visitor.
</Warning>

### Available APIs

| Class | Description |
|-------|-------------|
| `WidgetsApi` | Widget management |
| `CompositionsApi` | Composition management |
| `CanvasesApi` | Canvas operations |
| `ComponentsApi` | Component management |
| `TokensApi` | Token exchange and validation |
| `EntitlementsApi` | Feature access |
| `UsersApi` | User management |
| `ManagedUsersApi` | Partner user management and editor sessions |
| `PartnersApi` | Partner operations: contract, billing overview, credits, storage, notifications, analytics and presets |
| `CreditsApi` | Account credit balance and ledger |
| `InvoicesApi` | Invoices |

### Sending an Idempotency-Key

Most calls that make or change something need an `Idempotency-Key` header, such as creating a composition, a widget or a managed user (see [Idempotency](/docs/reference/idempotency)). Send it as `idempotencyKey` in the request object, and send the same one when you retry that call:

```javascript
import { randomUUID } from 'node:crypto';
import { CompositionsApi } from '@widgetic/api-sdk';

const compositions = new CompositionsApi(process.env.WIDGETIC_API_KEY);

const composition = await compositions.createComposition({
  newComposition,
  // Reuse the same key when you retry this call
  idempotencyKey: randomUUID()
});
```

The SDK does not insist on it: a call that needs a key and goes without one is answered by the API with `400`.

### Known Gaps in Version 1.0.29

The package is generated from the API description, and this version includes the partner calls for the contract, the billing overview, credits, storage, notifications, analytics and presets. When a call fails or a field is `undefined`, compare it with the [API Reference](/api-reference/introduction):

- **Some calls are typed to return nothing.** The API description gives no shape for their answer, so the SDK hands you no data from them. Among them are `getCurrentUser`, `getComponents`, `getComponent`, `updateWidget`, `getPartnerBillingOverview` and `getPartnerCreditTransactions`. Use the `Raw` twin of the call (the same name with `Raw` at the end), and read the body yourself:

  ```javascript
  import { PartnersApi } from '@widgetic/api-sdk';

  const partners = new PartnersApi(process.env.WIDGETIC_PARTNER_KEY);

  const response = await partners.getPartnerBillingOverviewRaw({ partnerId });
  const overview = await response.raw.json();
  ```

- **A request body and its answer do not name fields the same way.** The body you send to the partner calls names its fields in snake_case (`external_id`, `manager_id`), and the answer names them in camelCase (`externalId`). Read the camelCase name from an answer.

These come from the SDK build, not from the API. When a newer version is published, check this list again.

## Embed Script

To show a published widget on your pages, load the embed script from the Widgetic CDN and put a `<widgetic>` element where the widget should appear. There is nothing to install and no key in the page: showing a widget needs only the composition id.

```html
<script src="https://cdn.widgetic.com/sdks/browser/embed-sdk.js?v=6"></script>
<widgetic composition-id="COMPOSITION_ID" resize="fill-width" width="800" height="450" autoscale="on" adaptive="480" embed-target="site"></widgetic>
```

- **Several widgets on one page** work with one script tag.
- **Responsive**: `resize` and `adaptive` control how the widget fits its container.
- **`embed-target`** is `site` to put the widget inside the page, `overlay` to show it as a pop-up, or `mixed` for both. Overlay is the default, so use `site` for an ordinary embed.
- **Allowed websites**: if you limited the websites that may show your widgets, the script shows nothing on other websites. See [Security](/resources/security).

When you cannot load a script, use the frame instead:

```html
<iframe src="https://api.widgetic.com/embed/compositions/COMPOSITION_ID/frame" width="800" height="450" frameborder="0" allowfullscreen></iframe>
```

<Note>
  The embed script is not on npm: `npm install @widgetic/embed-sdk` finds nothing today.
</Note>

## UI SDK (Partners)

<Note>
  **Preview.** The UI SDK and the pieces it mounts are new. They are built and tested, and you can try them now, but small details can still change while this label is on.
</Note>

`@widgetic/ui-sdk` runs in your customer's browser. It downloads a piece (the File Browser, the composition editor or the widget creator) from Widgetic's CDN and draws it in your page, inside a shadow root, so your styles and its own do not touch each other. It never holds your API key: your server makes an [editor session](/docs/partners/editor-sessions) and the page only gets the token.

```bash
npm install @widgetic/ui-sdk
```

```javascript
import { mountModule } from '@widgetic/ui-sdk';

await mountModule('file-browser', {
  container: '#media-library',
  getToken: async () => (await fetch('/widgetic-session', { method: 'POST' })).json(), // { token, expiresAt }
  on: { select: ({ files }) => useFiles(files) },
});
```

See [UI Components](/docs/partners/ui-components) for the options and events, and [Canvas Embedding](/docs/partners/canvas-embedding) for the composition editor and the widget creator.
