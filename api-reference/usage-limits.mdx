The Widgetic API implements rate limits and usage quotas to ensure fair usage and service stability.

## Rate Limits

Requests are counted over a 15-minute window. A recognized API key is counted on its own, so one customer's traffic never uses up another's. Anything else is counted by IP address.

| Counted | Allowance |
|---------|-----------|
| An API key | About 3,000 requests per 15 minutes |
| A partner API key | 1,000,000 requests per 15 minutes |

The allowance that applies to a call is in the `RateLimit-Limit` header of its response, so read it there instead of hard-coding a number. The partner ceiling is there to stop a runaway loop, not to meter a platform that serves hundreds of thousands of its own users.

### Rate Limit Headers

Responses that were counted include rate limit information:

```
RateLimit-Limit: 3000
RateLimit-Remaining: 2995
RateLimit-Reset: 540
```

| Header | Description |
|--------|-------------|
| `RateLimit-Limit` | Maximum requests per window |
| `RateLimit-Remaining` | Requests remaining in window |
| `RateLimit-Reset` | Seconds until the window ends (a number of seconds to wait, not a timestamp) |

## When Rate Limited

If you exceed a limit, you'll receive a `429 Too Many Requests` response with a `Retry-After` header. `Retry-After` and `error.retryAfter` are the same number, in whole seconds:

```json
{
  "success": false,
  "message": "Too many requests, please try again later.",
  "error": {
    "code": "RATE_LIMIT_EXCEEDED",
    "message": "Too many requests, please try again later.",
    "retryAfter": 540,
    "details": { "limit": 3000 }
  }
}
```

`error.code` tells you which limit it was. See [Rate Limits](/docs/reference/rate-limits) for every code and for how to retry.

## Endpoint-Specific Limits

Some operations have a limit of their own, on top of the allowance on your key:

| Operation | Limit | Counted |
|-----------|-------|---------|
| Creating a widget | 120 per minute | For each account, across all of its keys |
| Billing operations | 20 per minute | For each person, across all of their keys |
| Events sent to a Zap | 60 per minute | For each Zap. Events over the limit are not sent |

AI generations are also held to a usage budget per hour and per day, and to a number of generations running at once. A refusal says which (`COST_LIMIT_EXCEEDED` or `CONCURRENCY_LIMIT_EXCEEDED`).

## Usage Quotas

### Plan Allowances

| Resource | Free | Solo | Teams | Partner |
|----------|------|------|-------|---------|
| AI credits | 100 starter credits, for the 7-day trial window | 400 a month | 2,000 a month for each member | By contract |
| Storage | 10 GB | 100 GB | 500 GB shared by the team | By contract |

One credit pays for one AI generation. See [Credits & Billing](/docs/partners/credits-billing#what-a-credit-costs) for what spends credits.

**Largest single file.** On Solo and Teams, a file can be up to 250 MB, whether it is uploaded in the app or saved to the media library by an AI assistant. On Free and Partner, a file saved by an assistant or sent in one request can be up to 10 MB, and a resumable upload from the app up to 100 MB. `GET /uploads/limits` returns the limit for the account that asks (`tus_max_bytes`).

### Checking Your Credits

Read the credit balance of the account behind your key. Credits left are `balance` minus `reservedBalance`:

```bash
curl -sS -H "Authorization: Bearer $WIDGETIC_API_KEY" \
  "https://api.widgetic.com/v1/credits/user/$WIDGETIC_ACCOUNT_ID/balance"
```

See [Credits & Billing](/docs/partners/credits-billing#checking-your-balance) for how to find your account id.

## Best Practices

### Implement Backoff

```typescript
import { ResponseError } from '@widgetic/api-sdk';

async function withBackoff<T>(call: () => Promise<T>, maxRetries = 3): Promise<T> {
  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    try {
      return await call();
    } catch (error) {
      if (!(error instanceof ResponseError) || error.response.status !== 429 || attempt === maxRetries) {
        throw error;
      }
      // Retry-After is a number of seconds. A CONCURRENCY_LIMIT_EXCEEDED refusal has none: wait a few seconds.
      const waitSeconds = Number(error.response.headers.get('Retry-After')) || 5;
      await new Promise((resolve) => setTimeout(resolve, waitSeconds * 1000));
    }
  }
  throw new Error('Max retries exceeded');
}
```

### Batch Operations

Use batch endpoints to reduce API calls:

```typescript
// Instead of one call for every widget
const { widgets: foundWidgets, errors } = await widgetsApi.getWidgetsBatch({
  getWidgetsBatchRequest: { widgetIds }
});
```

### Cache Responses

Cache read-only data to reduce API usage, and let it expire so that a change you make is picked up:

```typescript
const cache = new Map<string, { value: unknown; expiresAt: number }>();
const cacheLifetimeMs = 60_000;

async function getCachedComposition(id: string) {
  const cached = cache.get(id);
  if (cached && cached.expiresAt > Date.now()) {
    return cached.value;
  }

  const { data } = await compositionsApi.getCompositionById({ id });
  cache.set(id, { value: data, expiresAt: Date.now() + cacheLifetimeMs });
  return data;
}
```
