This page tracks changes that affect integrators. The [OpenAPI specification](/api-reference/introduction) is the source of truth for REST endpoints; the gateway's **tool contract** (currently **1.24.0** on the live MCP server; **1.25.0** is the one workspace model, below) is the source of truth for MCP tools.

## 2026

### November

- **One workspace model (tool contract 1.25.0, CLI, `GET /tokens/validate`):** there is no personal workspace any more: everyone works in workspaces, each with its own plan, credits and storage. An API key and an assistant's connection work in exactly one workspace, the one they were made for, and do not follow the workspace switcher of widgetic.com. In the MCP tools, `expected_workspace` takes a workspace's name and nothing else (`personal` is gone), `get_profile.workspace` is `{ name, plan }` (the `kind` field is gone), and the brand kit and media library tools act in the connection's workspace. A workspace in its free trial cannot connect an assistant or make a key yet, and a workspace whose plan has ended refuses every tool but `get_profile` and the ones that follow or cancel a build already started. `GET /tokens/validate` answers `workspace` (`id` and `name`, or `null`). A customer's keys are workspace keys (`wdg_org_`), made in the dashboard under Settings → API keys, and a workspace key can be limited the way a personal key could (Full access, Content, Read only or Custom). `POST /users/{id}/keys` answers `403` with the code `PERSONAL_API_KEY_RETIRED` for a customer's account and keeps making the keys of partner accounts; a personal `wgt_usr_` key made before keeps working until it is deleted or expires, and `organizationId` shows on it. The CLI follows: `widgetic auth login` and `widgetic auth status` say which workspace a key works in, and `widgetic doctor` shows its name and plan.
- **Credits per workspace (gateway 1.11.137, OpenAPI sync):** the public specification is refreshed from `api-gateway-service` (`npm run sync-openapi` in this repository). `GET /credits/user/{userId}/balance` and `GET /credits/user/{userId}/transactions` answer for the workspace the request acts in (a key that is not a team's acts in the person's own workspace) and can answer `503` when that workspace cannot be determined. The two partner credit routes answer for the account's whole balance and ledger, every workspace together. A `Widget` carries `publishedAt` and `hasUnpublishedChanges`, and an `Upload` carries `library_folder_path` when the file is part of a brand kit.
- **Brand Kit corner radius (docs and OpenAPI):** the REST routes and the MCP tool have refused a corner radius over 40 since 12 Nov 2026 (gateway 1.11.135, tool contract 1.24.0). The [Brand Kit](/docs/partners/brand-kit) page and the published OpenAPI description still said 64. Both say 40 now: `cornerRadius` of `PATCH /brand-kit` and the radius steps `radiusS`, `radiusM` and `radiusL` of `spacing`. Nothing changes for a request that already worked.
- **CLI 0.1.12:** `widgetic docs` prints the guide for AI agents, and `widgetic docs index` prints the index of every command, both from the installed version, offline and without an API key. The package also ships them as files in its `docs` folder. `widgetic mcp` has 56 commands (tool contract 1.24.0), and the [CLI reference](/docs/cli/commands/index) is the one this version generates: the one change to a command is that `--corner-radius` of `widgetic mcp update-brand-kit` takes at most 40, not 64. To set up an agent with the CLI, copy the prompt on the [quick start](/docs/quickstart#start-with-your-ai-agent).
- **Tool contract 1.23.0 (56 tools):** eight new tools. `get_embed_settings`, `save_embed_settings` and `apply_embed_code` show how a copy of a widget is embedded, save those settings, or copy the settings of a pasted Widgetic embed code onto it. `add_content_from_files` puts files from the media library on a widget's content list and shows a plan first. `get_workflow_guide` reads Widgetic's patterns for building a workflow. `get_translation_automation`, `save_translation_automation` and `refresh_translation` show and change Always translate and update one translation now from its original. They are on the [tools page](/docs/agents/tools) and, as `widgetic mcp <command>`, in the [CLI reference](/docs/cli/commands/mcp). `check-agent-docs-drift` compares the pages with gateway snapshot **1.23.0**.
- **CLI 0.1.10:** `widgetic mcp` has 56 commands (tool contract 1.23.0), and the [CLI reference](/docs/cli/commands/index) is the one this version generates.
- **Tool contract 1.22.0:** gateway snapshot **1.22.0** (48 tools), the one before 1.23.0.
- **MCP `replicate_widget` (gateway contract; docs updated for current server behaviour):** offers a stored browser-extension capture (`wgc_…`) as a copy. Nothing is built, no credits are charged and `show_widget` / `get_widget` are not used for the result.
- **OpenAPI sync:** public spec refreshed from `api-gateway-service` (`npm run sync-openapi` in this repository). The Brand Kit routes now say that `PUT /brand-kit` replaces the text styles and `PATCH /brand-kit` keeps them.
- **MCP placement (contract 1.21.0):** `create_widget`, `replicate_widget` and `create_widget_batch` respect the workspace you are signed in to on widgetic.com (`expected_workspace` optional argument).

### Earlier in 2026

See the [docs-site git history](https://github.com/widgetic/docs) for partner Brand Kit routes, workflow MCP tools, A/B test and translation tools (contract 1.15.0+), media library tools, and CLI command reference generation (`widgetic cli` 0.1.7+).

## How to stay current

<Steps>
  <Step title="Watch the OpenAPI file">
    Run `npm run check-openapi-drift` in this repository after gateway releases. Sync with `npm run sync-openapi` when it fails.
  </Step>
  <Step title="Watch MCP tool docs">
    Run `npm run check-agent-docs-drift` — it compares [tools](/docs/agents/tools) and [authentication](/docs/agents/authentication) with the gateway's contract snapshot and consent-page wording.
  </Step>
  <Step title="Watch the CLI">
    Bump `@widgetic/api-contracts` in the CLI, run `npm run docs`, and copy refreshed pages into `docs/cli/commands/`.
  </Step>
</Steps>

<Note>
  Mintlify deploys `main` of the [docs repository](https://github.com/widgetic/docs). Production API behaviour can lead the published docs briefly after a gateway deploy; the drift scripts above are meant to catch that before release.
</Note>
